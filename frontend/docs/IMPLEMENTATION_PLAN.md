# E-Catalog Tires — поэтапная реализация

## Аудит

- Vue 3, JavaScript, Vite, Vue Router; установлен motion. Pinia, Tailwind и Lucide пока отсутствуют.
- Шесть маршрутов: главная, каталог, корзина, о проекте, вход и регистрация.
- App.vue содержит RouterView. Шапки повторяются в страницах.
- Глобальные стили: assets/base.css через assets/main.css; каталог и корзина имеют scoped CSS.
- Каталог: шесть демонстрационных товаров, поиск, сезон, сортировка по цене, добавление в корзину.
- Корзина: localStorage ecatalog-cart и cartCount, количество, удаление. Эти ключи и ID товаров сохраняем.
- В frontend/src нет fetch, axios или Supabase-интеграций. Формы авторизации не отправляют данные; checkout показывает alert.
- В проекте есть build; frontend lint/test-команд нет.
- Backend и база данных вне области изменений. Движок базы не установлен аудитом frontend; описание MySQL в корневом README не является подтверждением.

## Части и сообщения коммитов

Каждая часть заканчивается проверкой сборки и отдельным отчётом. Коммиты пользователь делает самостоятельно.

1. **Подготовка (готово).** Единый набор существующих товаров, EUR/lv-LV, обозначение демонстрационных цен, lazy routes. Сохранены ID, цены и функции корзины.
   `refactor(frontend): centralize demo products and lazy-load routes`
2. **Дизайн-система и общий layout (готово).** Токены, типографика, базовые UI-компоненты, Lucide, адаптивная шапка и мобильное меню, footer, focus/reduced-motion. Локализация общих элементов. Не добавлять ссылки на ещё не реализованные страницы.
   `feat(ui): establish design system and responsive navigation`
3. **Главная и поиск (готово).** Hero, визуал шин, поиск по размеру/демо-автомобилю, сезоны и популярные товары. Совместимость требует проверки по документам автомобиля.
   `feat(home): add tire discovery homepage`
4. **Каталог.** Расширение единого набора данных, фильтры, сортировка, виды, пагинация, мобильные фильтры и состояния загрузки/ошибок/пустого результата.
   `feat(catalog): implement tire filters and product grid`
5. **Товар и предложения.** Детальная страница, характеристики, демонстрационные магазины, количество, единые правила расчёта доставки и итогов.
   `feat(product): add tire details and demo merchant offers`
6. **Избранное и сравнение.** Общий локальный state, безопасное чтение/запись localStorage, максимум четыре товара, сравнение характеристик и сохранение избранного.
   `feat(selection): add favorites and tire comparison`
7. **AI-чат.** Отдельный детерминированный mock service, категории запросов, история, повтор, контекст товара/сравнения, карточки из общего каталога, явная маркировка симуляции.
   `feat(ai): add contextual demo tire assistant`
8. **Мастер выбора.** Семь шагов, валидация, сохранение выбора, бюджет и приоритеты, рекомендации с объяснениями, общий контекст с чатом.
   `feat(ai): add guided tire selection wizard`
9. **Корзина.** Выбор предложения, количества, доставка, обратная связь и сохранение существующих пользовательских товаров.
   `feat(cart): add merchant-aware cart totals`
10. **Демо-checkout.** Контакты, доставка, способы оплаты без реквизитов карты, проверка полей, итог без реальной отправки заказа. Персональные данные не сохранять без необходимости.
    `feat(checkout): add validated demo checkout`
11. **Профиль, гараж, о проекте.** Локальные авто, редактирование, активный автомобиль и связь с поиском/чатом; демонстрационный профиль без имитации настоящей авторизации.
    `feat(account): add demo profile and vehicle garage`
12. **Финальная проверка.** Полная латышская локализация (включая lang документа), адаптивность, клавиатура, Escape/focus в диалогах, reduced motion, состояния, build и доступные проверки. Добавлять проверки для существенной логики расчётов и фильтров, а не для статических стилей.
    `fix(ui): refine accessibility and responsive behavior`

## Архитектурные решения

- Продолжать текущий проект; повторно использовать Router и cart API.
- src/data/products.js — единый источник demo-продуктов для будущих страниц и AI.
- src/utils/format.js — единый формат цен.
- Реальные API в будущем изолировать в services; симуляции — services/mock.
- Глобальное состояние вводить по мере необходимости, не устанавливать зависимости заранее.
- Все демонстрационные спецификации, наличие, рейтинги и цены должны быть явно обозначены; не выдавать их за проверенные тесты или реальные предложения.
